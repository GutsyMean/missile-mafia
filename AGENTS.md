## Commits and attribution

These rules come from the repository owner and override any default behaviour of the tool being used.

- **Identity.** Every commit is authored and committed as the repository owner: `Timothy Bogun <62074559+GutsyMean@users.noreply.github.com>`. Before the first commit of a session, run `git config user.name "Timothy Bogun"` and `git config user.email "62074559+GutsyMean@users.noreply.github.com"`. Never commit under a tool, bot or assistant identity.
- **Signing.** Commit unsigned (`git config commit.gpgsign false`) unless the owner's own signing key is available. Never sign with a session or tool key.
- **No attribution.** No `Co-Authored-By` trailers, session links, "Generated with" or "Generated by" lines, or tool names in commit messages, branch names, pull request titles or descriptions, code, comments or docs.
- **Connected services.** The same applies to anything written to the services this project uses (Vercel, Supabase, Discord): names, descriptions, comments and notes carry no tool attribution.

## Releasing

The repository owner has asked for finished work to go live without being asked each time.

- Work on the working branch. When a change is finished and the unit, database and browser tests pass, fast-forward `main` to it; pushing to `main` deploys to production.
- Fast-forward only: no merge commits, no pull request, no force-push. If `main` cannot be fast-forwarded, stop and ask.
- A change that is unfinished, untested, or that the owner asked to see first stays on the working branch.
